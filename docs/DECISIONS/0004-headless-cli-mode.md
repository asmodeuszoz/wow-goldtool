# ADR 0004 · Headless CLI mode inside the same binary

- **Status:** accepted
- **Date:** 2026-11-19
- **Discussion:** [docs/DEVELOPMENT.md](../DEVELOPMENT.md) · CI workflow `.github/workflows/ci.yml`

## Context

The data pipeline (API → SQLite → search/stats) must be testable and debuggable **without
a display server**, because:

* CI has no compositor;
* the desktop test machine is Wayland (KDE), where a hung GUI is hard to inspect;
* the sync takes minutes, so it must be observable from a terminal (progress, cancel,
  resume across runs);
* the app's own integration test should exercise the same code the GUI calls, not a copy.

## Options considered

| Option | Verdict |
| ------ | ------- |
| Separate `tools/sync` binary (`[[bin]]`) | Splits entry points; risks drift between tool and app behaviour |
| Separate test harness that re-implements command wiring | Duplicates the serialisation layer, weak test |
| **Subcommand mode in `main()`** before the GUI path | One binary, one code path; `cargo run -- status` works in RustRover's run config and in CI |

## Decision

`main()` inspects `argv`:

* first non-flag argument in `{status, sync, search, item, watch, stats, export}` →
  `cli::run(args)` and exit, **Tauri never constructed**;
* otherwise (no args, or flags like `--help`) → `gui::run()`.

Rules:

* every subcommand prints JSON on stdout and human text on stderr, so it is pipeable to
  `jq` and still readable in a terminal;
* `--db <path>` and `--fixture <url>` override env-derived paths (`WGT_DB`, `WGT_FIXTURE`);
* `sync` prints progress lines (`done/total`, rate, phase) and honours `--budget` so tests
  can crawl a small fixture;
* exit codes: `0` ok · `2` usage · `3` network/rate-limit failure · `4` DB error;
* Tauri never touches the DB, so the CLI is the only headless writer and the GUI worker
  thread is the only headful writer — both go through `sync.rs`.

## Consequences

* **Gained:** CI can run `cargo run -- stats` on a seeded fixture DB as a real regression
  gate; a developer can watch a 2-minute list crawl in a terminal; `cargo test` and the
  CLI share the exact `sync.rs`/`query.rs` code the UI invokes.
* **Given up:** the binary's `--help` is hand-written, not generated by a CLI framework
  (no `argparse`-style dep) — deliberate: fewer deps, and the flag set is small.
* Arg parsing is shared with the GUI path, so a future flag (`--db`) must stay a no-op
  for the GUI or be forwarded to `AppState`.
